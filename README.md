### 🌡️ [RTOS Thermal Monitoring System](https://github.com/SIDDUSPACE/rtos-thermal-monitoring-system)

![ESP32](https://img.shields.io/badge/ESP32-0D1117?style=flat-square&logo=espressif&logoColor=00C8FF&labelColor=0D1117)
![FreeRTOS](https://img.shields.io/badge/FreeRTOS-0D1117?style=flat-square&logoColor=00C8FF&labelColor=0D1117)
![C](https://img.shields.io/badge/C_90%25-0D1117?style=flat-square&logo=c&logoColor=00C8FF&labelColor=0D1117)

Real-time thermal & humidity monitoring firmware using FreeRTOS on ESP32 — 4 concurrent tasks with queue-based data transfer and semaphore-driven emergency alerts.

- Priority-scheduled tasks: Sensor · Monitor · Control · Comms
- Queue-based sensor data pipeline between tasks
- Binary semaphore for emergency event signaling
- Threshold-driven cooling & humidity alert logic

<td width="50%" valign="top">

### 🔴 [Firmware Crash Analyzer](https://github.com/SIDDUSPACE/firmware-crash-analyzer)

![ARM](https://img.shields.io/badge/ARM%20Cortex--M-0D1117?style=flat-square&logoColor=00C8FF&labelColor=0D1117)
![Assembly](https://img.shields.io/badge/C%20%7C%20ASM-0D1117?style=flat-square&logoColor=00C8FF&labelColor=0D1117)
![Renode](https://img.shields.io/badge/Renode-0D1117?style=flat-square&logoColor=00C8FF&labelColor=0D1117)

Silicon-grade HardFault analysis framework for ARM Cortex-M. Captures CPU state on crash, persists the record across reboot, and resolves the faulting instruction to source line.

- Assembly handler captures R0–R12, LR, PC, xPSR on fault
- Reads CFSR / HFSR / BFAR fault status registers
- Post-mortem `addr2line` symbolication to exact file & line
- CI validated via GitHub Actions on every push

</td>
</tr>

### 🔐 [Secure IoT Firmware & Device Auth](https://github.com/SIDDUSPACE/Secure-IoT-Firmware-Device-Auth)

![ESP32](https://img.shields.io/badge/ESP32%20%2B%20QEMU-0D1117?style=flat-square&logo=espressif&logoColor=00C8FF&labelColor=0D1117)
![SecureBoot](https://img.shields.io/badge/Secure%20Boot-0D1117?style=flat-square&logoColor=00C8FF&labelColor=0D1117)
![mTLS](https://img.shields.io/badge/mTLS%20%7C%20X.509-0D1117?style=flat-square&logoColor=00C8FF&labelColor=0D1117)
![C](https://img.shields.io/badge/C%2067%25%20%7C%20Python%2031%25-0D1117?style=flat-square&logo=c&logoColor=00C8FF&labelColor=0D1117)

End-to-end secure IoT architecture for ESP32 — covering secure boot, firmware integrity verification, mutual TLS device authentication, and certificate revocation. Fully validated using QEMU simulation.

| Threat | Mitigation |
|---|---|
| Firmware tampering | Manifest signature verification |
| Rogue / cloned device | mTLS + Device CA validation |
| Stolen certificate | Certificate Revocation List (CRL) |
| MITM attack | TLS encrypted channel |
| Unauthorized access | Backend authorization logic |
